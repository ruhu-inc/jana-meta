Jana Architecture

Jana is a personal tutor and study companion for adults, built on Meta's models. A learner brings their own material or follows a curriculum. Jana teaches from it, checks the work, remembers the learner and keeps saved study working when the connection drops.

This document starts with what Jana can do and then opens each part: what the learner gets, which components do the work, how they connect, and the code that implements it.

Rule

Code decides, the model phrases

The engine sets the step, holds the hint level and renders the facts. A model drafts words and chooses tools inside that step.

Rule

Nothing is said until it passes

A reply stays private until its gates pass. A number must trace to a check, the question or the learner.

Rule

A verdict comes from a key or a tool

What could not be checked is labelled "Judged, not checked" and is never counted as mastery.

Rule

The record stays with the learner

Learner data is stored on the device. Each kind of data that goes online has its own consent, and the record of what left is kept.

Checking, the board and photos

A learner's working is checked line by line, by code, against the line before it. Supported steps are checked without requiring a single prescribed solution path, and a step that cannot be checked stays unverified. Photos reach the same checks once the learner has confirmed how Jana read them.

Learner benefitFeedback lands on the exact line, on the learner's own page, without forcing one solution path.
ComponentsClient board, perception worker, Muse Spark or Glimmer vision, tool worker, SAM 3.1 through the gateway.
FlowScreen the photo, read it, the learner confirms, each line is checked, then the first wrong line is outlined.
Code decides, model judgesCode: every verdict, the choice of line, the answer gate. Model: reading the handwriting and proposing boxes, which the learner confirms.

Worked example: real checker output

Output of math_check_step on this revision. Two supported methods pass, and wrong lines get a category and a reason. No model is involved.

Previous lineNext lineVerdictReason given

The checker is SymPy and Pint behind its own parser, in a sandboxed process with restricted imports. Each slice has an 800 ms budget and answers "unknown" rather than guessing. An "unverifiable" result creates no mastery evidence. tests/test_false_accepts.py, where each case was a reproduced false accept: Passed, 4 Nov.

"Snap your sketch" reads the elements of a drawing and code compares them with the checked figure. It covers motion graphs and free-body diagrams only. The face gate sees faces, not bodies. There is no dedicated local handwriting OCR engine: handwritten working relies on the selected vision model, with the learner confirming the transcription. The local vision path needs Glimmer's projector and a compatible runtime. It read a prepared solution correctly on an Apple M4 Max, and real handwriting is not tested. SAM outlines need connectivity.

Study: from source to checked quiz

A learner adds their own material on any subject and gets study aids cited to it. A draft has to survive a second model check and an exact match against the source before it is saved.

Learner benefitEvery explanation and question can be traced to the learner's own page, and saved aids stay usable offline.
ComponentsClient workspace, core Study desk and queue, gateway Study route, sandboxed study worker, Muse Spark.
FlowUpload, extract, freeze chunks, draft, support check, span check, save, then mark.
Code decides, model judgesCode: consent, chunking, span match, structure, keys, and what is saved. Model: drafting and judging support, which the same model family does.

// held apart from the view, in "keys"
{ "item_id": "q1", "answer": "a", "marking": "judged" }
// on the aid that holds the quiz
"made_by": { "runtime": "online", "model": "muse-spark-1.3" }
// the learner's attempt
{ "item_id": "q1", "verdict": "correct", "marking": "judged",
  "label": "Judged, not checked" }
  1. Traceable to the source. Each citation names a source revision, a chunk and a character span. This is how "open the original slide" works.
  2. The answer is held apart. The learner's view has no key, so the interface cannot leak it.
  3. Honest about how it was marked. marking says whether code proved the verdict or it was judged, and the label comes from it. Study never counts as mastery.
  4. Says who made it. made_by records the route and the exact model, and the provenance line on the page is drawn from it.

Your tutor and learner memory

Each learner has one continuing conversation with a tutor that remembers them. Code fetches the facts and checks the wording, so progress numbers have to come from tools. The learner can see and change what is remembered.

Learner benefitThe tutor continues from last time and can explain why it personalises, and the learner stays in control.
ComponentsCompanion, Reflector, learner database, memory tools, consent switches, "What your tutor knows".
FlowEvents become notes at write points. A later session recalls them under a bound, filtered by route and consent.
Code decides, model judgesCode: routing, recall, facts, actions, gates, what is stored. Model: wording, tool choice and proposing notes, which a filter can refuse whole.

Muse Spark: role selection and requests

Each role names a tier in the router configuration. The Solver prefers the cloud and needs tools. The gateway then maps the requested effort per model alias and adapts the request to what Muse Spark accepts.

Jana uses Standard mode and sends store: false on supported requests. Provider retention follows the applicable Meta account settings and policies, and this flag alone does not establish Zero Data Retention (field reference, Zero Data Retention).

Muse Glimmer: local attachment and routing

The launcher starts llama-server on loopback with pinned weights. The router marks the cloud offline after a failed probe and brings it back when a probe succeeds.

SAM 3.1: the segmentation path

Muse Spark returns a box per region. The core asks the gateway to sharpen them, and the gateway meters the call and sends the prompts to SAM. A failed or empty result leaves the box as Spark read it.

Voice Transcribe: streaming

The gateway opens the realtime socket and sends the setup frame first, then 24 kHz audio at real time. Each partial replaces the last. Words spoken back come only from accepted turns.

Status and limits

Jana works end to end on real models, and most of the engineering is tested. It has not yet been shown to improve learning, and it is not a signed, released product.

Real limits

  • No learning-gain study. None has been run, and no outcome is claimed. A simulated multi-day journey is covered by regression tests.
  • No release path. Signing uses a test root, hosts are placeholders and TLS pins are empty. Browser and hosted cores run as non-release.
  • No encryption at rest for learner databases, and no profile PIN.
  • Evidence predates Muse in places. Prompt snapshots cover earlier local models, some live and perception runs predate this stack, and no model bake-off is recorded. The router also still lists earlier local candidates, used only if one is already installed.
  • Curriculum review. Packs are AI-drafted and answers are recomputed by tools, without recorded human review.
  • Thin content in new features. 10 root-gap links, 8 predict scenarios, few figures, and no grade bands or diagnostic anchors.
  • The verifier is the same model family as the drafter for Study, and the device trusts the gateway's support filter, rechecking only the spans.
  • Local tutoring needs GPU-class hardware. Text tutoring, guided tutoring and photo reading work on Muse Glimmer on an Apple M4 Max, at 22 to 122 seconds per reply, and on a 24 GB NVIDIA L4 in the cloud, at 23 to 49 seconds. It peaked at 20.7 GB of GPU memory. With no GPU it is not usable, and the learner gets a plain message after 240 seconds. No laptop other than the M4 Max is tested, including typical 32 GB machines.
  • Local role limits are longer. A delegated role on the local model gets three times its limit: Checker 30 s, Diagnoser 90 s, Solver 180 s. On the lean local class the Checker is skipped when code has already marked a line wrong. A slower machine can still hit these limits, and then falls back.
  • No release desktop app. A debug build works with a test-signed manifest and a manual override. A release build needs an agent bundle signed under a real release root, a pinned llama.cpp, and real hosts and pins. A speed test under load can also drop a machine to content-only, with no way to retest in the interface. No Windows build has been made.
  • Study does not generate offline, and uploads made offline wait for the internet. This is a deliberate setting.
  • Service end date. Cloud calls stop on 9 November 00:00 UTC by configuration, and the Meta credit's real end date is unconfirmed.
  • One person holds every role, and CODEOWNERS still names a service that no longer exists.
